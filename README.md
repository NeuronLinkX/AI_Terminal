# MacAIterm

실제 셸(PTY)과 자연어 AI 에이전트를 합친 macOS 터미널 앱입니다.
"3000번 포트 쓰는 프로세스 확인해줘", "이 테스트가 실패해, 고쳐줘" 처럼 지시하면 AI가 **같은 셸·같은 디렉터리**에서 명령을 실행하고, 종료코드와 출력을 보고 다음 단계를 정하며, 실패하면 원인을 분석해 제한된 횟수 안에서 고칩니다. 코드 읽기·부분 수정·테스트 재실행까지 하는 **코딩 에이전트**로도 동작합니다.

![개요](docs/screenshots/01-overview-dark.png)

> **이름 변경**: 이 앱의 이전 이름은 *AI Terminal* 입니다. 이름이 바뀌면서 앱 데이터 폴더도 `~/Library/Application Support/AI Terminal` → `MacAIterm` 이 되었고, **처음 실행할 때 설정·탭·기록·감사 기록·사용량·프로젝트 규칙·저장한 SSH 세션을 새 폴더로 복사**합니다(원래 폴더는 그대로 둠). 설정 창에 직접 저장해 둔 **API 키는 키체인 항목 이름이 앱 이름을 따르므로 복사되지 않으니 다시 입력**하세요(`OPENAI_API_KEY` 환경변수는 그대로 동작). 이전 `/Applications/AI Terminal.app` 은 지우셔도 됩니다.

## 주요 기능

**화면 구성** —왼쪽: 실제 zsh 터미널(대화형 프로그램, ANSI 색상, 리사이즈, Ctrl+C) / 오른쪽: AI 타임라인(설명·명령 카드·승인 카드·파일 diff·실행 요약) / 하단: 입력창. 입력창의 `AI` 모드는 자연어를 AI에게, `$ 셸` 모드는 명령을 터미널로 보냅니다(⌘J 또는 Shift+Tab 전환, AI 모드에서 `!명령` 은 셸 직접 실행).

**상단 바** — 현재 디렉터리, **CPU · GPU 사용률 · 가용 메모리 · 메모리에 올라간 모델** 표시줄(2초마다 갱신, 창이 가려지면 중단; SSH 접속 중이면 탭 아래에 **서버의** CPU·메모리·GPU·디스크 띠가 함께 표시), 작업 상태, 연결된 모델, 중단 / 출력 복사 / 세션 초기화, 우측 끝에 **실행 중인 앱의 빌드 시각**.

**탭** — ⌘T 새 탭(현재 탭의 디렉터리에서 시작) · ⌘W 닫기 · ⌘1~9 이동 · ⌘⇧[ / ⌘⇧] 이전/다음. 탭 점이 상태(AI 작업 / 승인 대기 / 셸 실행)를 보여줍니다.

**권한과 승인** — 하단 방패 아이콘으로 모드 선택(읽기 전용 / 기본 / 모든 명령 확인 / 신뢰). 위험한 명령은 입력창 위 승인 바에서 `1 한 번만(⌘⏎)` · `2 이 세션 항상 허용(⌘⇧⏎)` · `3 거부(Esc)` · 거부하며 의견 입력 중에서 고릅니다. "항상 허용"은 `git push`·`brew install` 같은 종류 단위, `rm`·`kill` 같은 파괴적 명령은 그 명령 한 줄만 허용하며, sudo·강제 옵션·`curl | sh` 는 선택지가 없습니다.

**코딩 에이전트** — `read_file`(줄 범위 지정) → `edit_file`(정확히 한 곳만 일치하는 부분 수정) / `write_file`(새 파일) → 테스트·빌드·린트 실행 → 실패 시 수정 반복(최대 16단계, 연속 실패 3회 중단). 파일 변경은 diff 로 보여주고 원본을 백업하며 카드의 **"이 변경 되돌리기"** 로 한 번에 복구합니다.

**메모리 관리** — 모델은 AI에게 요청할 때만 메모리에 올라오고, 5분간 요청이 없으면 내려갑니다. **탭이나 창을 닫으면** 진행 중이던 모델 호출을 취소하고, 다른 탭이 쓰고 있지 않으면 **즉시 메모리에서 내립니다**(앱 종료 시에도). 상단 바에 `qwen3:8b 대기 · 메모리 비움` / `qwen3:8b 5.2GB 적재됨` 으로 표시됩니다.

**설정 창** — 상단 톱니바퀴 또는 ⌘, . (이 문단은 모델·메모리 항목이며, 언어·글꼴·커서·네트워크 차단·세션 기록·감사 기록·단축키·업데이트·**KV 캐시 정밀도**·**프롬프트 압축**·**OpenAI 호환 서버/API 키/토큰 사용량** 항목도 같은 창에 있습니다.) 컨텍스트 길이(4K~32K, 선택한 값의 **예상 메모리**와 전체 메모리 대비 비율 표시, 바꾸면 모델을 다시 불러옴) · 모델 메모리 유지 시간(즉시 해제/1/5/15/30분) · 탭·창 닫을 때 모델 즉시 내리기 · 상단 GPU·메모리 표시 켜기/끄기 · 새 탭의 기본 권한 모드(`신뢰`는 기본값으로 둘 수 없음). 바꾸는 즉시 저장·적용됩니다(예: 컨텍스트 12K → 8K 로 바꾸면 `qwen3:8b` 가 7.1GB → 6.5GB 로 올라옴, 위 스크린샷). 설정 파일은 `~/Library/Application Support/MacAIterm/settings.json` 이고, AI에게 보내는 문맥 크기도 컨텍스트 설정에 맞춰 자동 조절됩니다.

### SSH 서버 접속 (MobaXterm 처럼)

터미널 탭에서 `ssh` 로 서버에 들어가면 앱이 접속을 알아보고 **① 서버에서 일하는 AI**, **② 서버 CPU·메모리·GPU·디스크 모니터(이 Mac 의 사용량과 동시에 표시)**, **③ 왼쪽 사이드 바 — 세션 관리자와 서버 ⇄ 이 Mac 폴더 트리(드래그 복사)** 를 더해 줍니다. 자세한 사용법·안전장치·한계는 **[docs/SSH.md](docs/SSH.md)**.

| | |
| --- | --- |
| ![세션 관리자](docs/screenshots/60-ssh-sessions.png)**세션 관리자** — 저장 세션·폴더·`~/.ssh/config`·최근 접속(비밀번호는 저장하지 않음) | ![서버·이 Mac 폴더 트리](docs/screenshots/61-ssh-files.png)**서버(위) / 이 Mac(아래) 폴더 트리** + 탭 아래 **서버 CPU·메모리·GPU·디스크** 띠 |
| ![전송](docs/screenshots/62-ssh-transfers.png)**드래그로 복사** — 진행률·`완료 · 검증됨`(SHA-256) | ![서버 상태](docs/screenshots/63-ssh-status.png)**서버 상태** — 그래프와 이 Mac 과 나란히 비교 |
| ![서버에서 AI](docs/screenshots/64-ssh-ai.png)**서버에서 일하는 AI**(실제 로컬 모델) | ![승인](docs/screenshots/65-ssh-approval.png)서버를 바꾸는 명령은 **서버 이름이 적힌 승인** |

- 화면의 "서버"는 **이 Mac 자신(127.0.0.1)에 임시로 띄운 SSH 서버**(키 로그인)입니다. 그래서 서버 OS 가 `Darwin`, GPU 가 Apple GPU 로 나옵니다. 리눅스 서버는 `/proc`, NVIDIA GPU 는 `nvidia-smi` 에서 읽습니다.
- **비밀번호·키 암호는 받지도 저장하지도 않습니다**(터미널에서 직접 입력). 모니터·파일 패널은 프롬프트를 띄울 수 없는 별도 연결(`BatchMode`)로 동작하므로 키 로그인이나 세션 메뉴로 연 접속에서 동작합니다.
- 서버를 바꾸는 명령·파일 쓰기는 항상 승인을 받고, `free` · `df` · `nvidia-smi` 같은 읽기 전용 점검은 바로 실행합니다. 허용 규칙은 그 서버에서만, 세션 동안만 유효합니다.
- 시험: 실제 `sshd`(127.0.0.1, 임시 키)를 쓰는 통합 시험과 실제 Electron 창 e2e(`node scripts/e2e-features.js ssh`), 그리고 실제 Ubuntu(aarch64) 가상 머신에 키 로그인으로 서버 모니터·파일 엔진·AI 원격 파일 도구를 돌린 확인(`scripts/verify-ssh-vm.js`, 27항목 통과). NVIDIA GPU 서버는 DGX Spark(GB10) 한 대에서 접속·서버 모니터만 확인했습니다(`scripts/verify-ssh-alias.js`). **창 화면을 실제 리눅스/GPU 서버에 붙여 본 것은 아니고, 비밀번호만 되는 서버는 시험하지 못했습니다.** X11 은 XQuartz 가 필요하고, Finder 로 끌어내기는 25 MB 이하 파일에 한해 가능한 범위에서만 동작합니다.

### 메모리 사용량 벤치마크 (Apple M4 · 16GB 기준 실측)

로컬 모델은 **가중치 전체 + 대화 기억 공간(KV 캐시)** 을 메모리에 올립니다. Apple Silicon 은 CPU 와 GPU 가 **같은 메모리**를 나눠 쓰므로 16GB 중 절반 가까이를 모델이 차지할 수 있습니다.

> 아래 숫자는 모두 **아래 측정 환경에서 측정 스크립트로 실제로 잰 값**입니다(원본: `docs/benchmark-memory.json`, 표는 `scripts/bench-report.js` 가 JSON 에서 자동 생성). 다른 Mac 에서는 값이 달라집니다 — 아래 "재현 방법"으로 직접 측정할 수 있습니다.

**측정 환경**: Apple M4 · 통합 메모리 16GB · macOS 27.0.1 · Ollama 0.34.1 · MacAIterm v0.1.0 · 2026-10-03. 브라우저·메신저·편집기 등 다른 앱이 실행 중인 **일반 사용 상태**에서 측정했으므로 "가용 메모리"는 측정 당시의 다른 앱 상황에 따른 참고값입니다.

**방법**: 모델을 모두 내린 뒤 → 처음 불러오며 한 번 생성 → 2번 더 생성(고정 질문, 120토큰). 올라온 크기는 `ollama ps` 의 SIZE 와 같은 값, 속도는 3번의 중앙값, 가용 메모리는 `vm_stat` 의 (빈 공간 + 비활성 + 투기적 + 정리 가능) 입니다.

**읽는 법**

- **컨텍스트가 클수록 메모리가 늘고 속도는 거의 그대로**입니다. `qwen3:8b` 는 4K 5.6GB → 32K 10.3GB 로 늘지만 속도는 18.7~19.6 tok/s 로 일정합니다.
- **`qwen3:14b` 는 8B 의 약 55% 속도**(10.7 vs 19 tok/s, 16K 에서는 9.0)이고 **10.7~12.5GB** 를 차지합니다. 16GB Mac 에서는 올린 직후 가용 메모리가 0.5~0.7GB 까지 떨어졌습니다 — 측정 환경(16GB)에서는 권장하지 않습니다.
- **`qwen3:8b` 기본 설정(12K)도 올린 직후 가용이 1.8GB** 까지 내려갔습니다(다른 앱이 켜진 상태). 16GB 에서 큰 앱을 함께 쓰면 빠듯하다는 뜻이며, 설정에서 컨텍스트를 8K 로 낮추면 0.6GB 를 아낄 수 있습니다.
- 설정 창의 **"예상 메모리"**(모델 크기 + 컨텍스트 × 0.15MB)는 `qwen3:8b` 실측과 ±0.2GB 이내로 맞았습니다(`qwen3:14b` 16K 는 0.7GB 낮게 나옴).
- **MacAIterm 앱 자체는 유휴(탭 1개) 약 479MB** 입니다(Electron 프로세스 5개의 RSS 합계 — 프로세스 간 공유 메모리가 중복 집계되어 실제보다 크게 보일 수 있음). 모델이 내려가 있으면 AI 관련 메모리는 이 값뿐입니다.
- 8GB 이하 Mac 은 측정하지 않았습니다(8B 모델만 5.6GB 이상이라 권장하지 않음).

줄이는 방법

- **자동**: 5분간 요청이 없으면 모델이 내려가고, **탭·창을 닫으면 즉시** 내려갑니다(앱 종료 시에도). 표시가 `메모리 비움` 이면 모델 몫은 0 입니다.
- **컨텍스트 줄이기**: **설정(⌘,) → 컨텍스트 길이**를 8K 로 낮추면 대화 기억 공간(KV 캐시)이 줄어 12K 대비 약 0.6GB 절약됩니다(실측: `qwen3:8b` 4K 5.6GB · 8K 6.5GB · 12K 7.1GB · 16K 7.8GB). 긴 대화·큰 파일에서 앞부분이 잘릴 위험이 조금 늘어납니다. (환경변수 `AIT_OLLAMA_CTX` 는 설정을 저장하기 전의 기본값만 정합니다.)
- **유지 시간 줄이기**: 설정에서 `1분` 이나 `즉시 해제` 를 고르면 더 빨리 내려갑니다(다음 응답이 처음 불러오는 시간만큼 느려짐 — 디스크 캐시에 있으면 1~4초, 없으면 10~20초).
- **다른 앱 닫기**: 브라우저·편집기처럼 메모리를 많이 쓰는 앱을 닫으면 가용이 바로 늘어납니다.
- **14B 는 필요할 때만** 모델 칩에서 선택하세요.

## 설치 (DMG)

```bash
open dist/MacAIterm-*-arm64.dmg      # 내려받았거나 직접 빌드한 DMG (Intel Mac 이면 -x64.dmg) — MacAIterm 을 Applications 로 드래그
```

1. 처음 실행은 서명이 없는 앱(ad-hoc)이라 Finder 에서 **우클릭 → 열기**. 계속 막히면 `xattr -dr com.apple.quarantine "/Applications/MacAIterm.app"`
2. Dock 에 유지: 실행 중인 Dock 아이콘 우클릭 → 옵션 → Dock에 유지
3. 새 버전을 설치했는데 옛 화면이 보이면: 앱을 **완전히 종료(⌘Q)** 했다가 다시 켜세요. 화면 우측 상단의 `v0.1.0 · 월/일 시:분 빌드` 가 설치한 빌드 시각과 같아야 합니다.

지원: macOS (Apple Silicon · Intel). **빌드는 현재 Mac 의 CPU 를 자동 감지**하므로 설정 파일을 고칠 필요가 없습니다. 다른 CPU 용으로 만들 때만 아래 명령을 쓰세요.

**다시 빌드하려면**

```bash
npm install && npm run dist      # 빌드하는 Mac 의 CPU(arm64 / x64)에 맞춰 자동 빌드 → dist/ 에 DMG·ZIP 생성 (빌드 시각 자동 기록)
```

| 목적                        | 명령                           | 결과 파일                                          |
| --------------------------- | ------------------------------ | -------------------------------------------------- |
| 빌드한 Mac 용 (자동 감지)   | `npm run dist`               | `MacAIterm-<버전>-arm64.dmg` 또는 `-x64.dmg` |

## 시연 영상 자동 실행 (`npm run demo`)

화면 녹화(YouTube 등)를 위해 시연을 **자동으로** 진행합니다. 녹화를 시작하고 카운트다운이 끝나면 실제 앱이 기본 로컬 모델(Ollama)로 ① 실패하는 테스트를 고치고 ② 삭제 전에 승인을 받고 ③ `ssh dgx` 로 서버에 접속해 GPU 상태를 조회하고 ④ 서버 파일 삭제를 승인 창에서 거부하는 과정을 실시간으로 보여 줍니다. 빠르게 감거나 꾸미지 않습니다.

```bash
npm run demo                                         # 한국어 · 다크 · 15초 카운트다운 · ssh dgx 포함
npm run demo -- --lang=en --theme=light --countdown=30
npm run demo -- --no-ssh                             # 서버 장면 없이
npm run demo -- --manual                             # 카운트다운 대신 `touch /private/tmp/ait-demo-go` 신호로 시작
```

- **녹화까지 자동으로**: `npm run record` 는 위 시연을 진행하면서 앱 창을 스스로 녹화해 `~/Movies/MacAIterm-demo-<언어>-<날짜>.mp4` 를 만듭니다(권한 불필요, 창 안쪽만 찍으므로 메뉴 막대와 다른 창은 들어가지 않습니다). 기본 `tight` 모드는 채팅이 저절로 진행되는 모든 변화를 담되 모델이 생각하는 대기 시간을 줄여 1분 안팎의 영상으로 만들고, `--record-mode=real` 은 실제 시간 그대로 담습니다. 끝나면 영상 속 글자를 OCR 로 읽어 계정·호스트 이름이 보이는지 검사하고, 보이면 파일 이름에 `-CHECK-PRIVACY` 를 붙입니다. `ffmpeg` 가 필요합니다(`brew install ffmpeg`).
- 녹화는 화면 전체가 아니라 **이 창만**(⌘⇧5 → "선택한 부분 기록") 하세요. 메뉴 막대와 다른 앱은 스크립트가 보호할 수 없습니다.
- **홍보 영상 모드(기본)**: `npm run record` 는 영어 UI · 밝은 테마로 약 2분(`--target=120`) 영상을 만듭니다. 마우스 포인터(클릭 파문 포함)가 보이고, 장면마다 부드럽게 확대되며, 하단에 장면 자막이 나오고, 처음과 끝에 앱 아이콘 카드가 붙습니다. 장면은 에이전트 코딩 → 터미널 검색 → 계획 모드 → 삭제 승인 → 세션 기록 → 모델·설정 → 화면 분할 → 저장된 SSH 세션 → `ssh dgx` 접속 → 드래그 앤 드롭 전송 → 서버 상태 → 서버의 에이전트 → 서버 승인 순서이고, 실패한 장면은 건너뛰고 마지막에 알려 줍니다. `--plain` 은 효과 없이, `--short` 는 핵심 장면만(약 1분), `--lang=ko` 는 한국어, `--theme=dark` 는 어두운 테마입니다. 효과만 30초 안에 확인하려면 `npm run record -- --fxtest` 를 쓰세요.
- 개인 정보: 이 Mac과 서버의 계정·호스트 이름과 모든 IP 주소는 화면에 나타나는 순간 가상의 이름으로 바뀌고, ssh 로그인 중(배너, 호스트 이름, 홈 폴더)에는 창이 흐림 막으로 덮입니다. 무언가 새어 나오면 감시 장치가 창을 다시 덮고 마지막에 알려 줍니다. 서버에는 `/tmp` 의 임시 폴더 하나만 만들고 끝나면 지웁니다. 키 로그인만 쓰며 비밀번호는 다루지 않습니다.
- 끝나면 이번 촬영의 결과(고침/승인/거부/개인 정보 여부)가 ✓/✗ 로 출력됩니다. ✗ 가 있으면 다시 실행해 새로 찍으세요. 작은 로컬 모델은 가끔 같은 동작을 반복하므로 두세 번 찍어 가장 좋은 것을 쓰는 편이 좋습니다.

## 다운로드 웹 페이지 (`site/`)

사람들이 DMG 를 내려받을 수 있는 소개·다운로드 페이지입니다(한국어/English, 라이트/다크, 쿠키·분석 도구·외부 글꼴 없음). `index.html`(소개) 과 `download.html`(.dmg · .zip · 설치 방법 · 요구사항 · 변경 내역 · 체크섬) 두 쪽이고, 순수 HTML/CSS/JS 라 서버 없이 어디에나 올릴 수 있습니다.

```bash
npm run dist            # dist/MacAIterm-<버전>-arm64.dmg / .zip
npm run site            # 버전·파일 크기·SHA-256·스크린샷을 site/ 에 반영 (다운로드 링크는 GitHub Release 주소)
npm run site:local      # 같은 작업 + DMG/ZIP 을 site/downloads/ 에 복사해 상대 링크로 (미리보기용, git 에 올라가지 않음)
cd site && python3 -m http.server 8080     # http://localhost:8080 에서 미리보기
```

- **파일 올리기**: 페이지의 다운로드 버튼은 `https://github.com/NeuronLinkX/macAIterm/releases/download/v<버전>/MacAIterm-<버전>-arm64.dmg` 로 연결됩니다. 이 주소가 열리려면 같은 이름의 파일을 GitHub Release 에 올려야 합니다(`git tag v0.1.0 && git push --tags` 로 CI 가 만들게 하거나, 직접 만든 파일을 `gh release create v0.1.0 dist/MacAIterm-0.1.0-arm64.dmg dist/MacAIterm-0.1.0-arm64.zip` 로 올림).
- **웹에 공개**: 저장소 *Settings → Pages → Source: GitHub Actions* 를 한 번 켜면 `site/` 가 바뀔 때마다 `.github/workflows/pages.yml` 이 배포합니다. 다른 호스팅(Netlify · 자체 서버 등)은 `site/` 폴더를 그대로 올리면 됩니다.
- **두 벌(영어 / 한국어)**: 영어 페이지는 `site/*.html`, 한국어 페이지는 `site/ko/*.html` 이고 헤더의 `English` / `한국어` 링크로 서로 오갑니다. 스크린샷은 언어별로 따로 있습니다(`assets/img/*.png`, `assets/img/ko/*.png`). 문구를 고칠 때는 두 쪽을 같이 고치세요.
- **스크린샷 다시 찍기**: `AIT_APP_BIN=… AIT_SHOT_DIR=/tmp/site-shots node scripts/shots-site.js dgx` (영어), `SHOTS_LANG=ko AIT_SHOT_DIR=/tmp/site-shots-ko …` (한국어). 이어서 `node scripts/build-site.js --shots /tmp/site-shots --shots-ko /tmp/site-shots-ko`. 촬영 전에는 계정·호스트 이름이 화면에 없는지 확인하세요(스크립트가 검사하지만 OCR 로도 확인).
- **문의**: 별도의 문의 페이지와 폼은 없고, 모든 페이지 맨 아래(푸터)에 이메일 주소가 적혀 있습니다. 주소를 바꿀 때는 `site/*.html` 과 `site/ko/*.html` 의 푸터를 같이 고치세요.
- **문장 줄바꿈**: 페이지 문구는 문장이 끝날 때마다 줄이 바뀝니다. 문구를 고친 뒤에는 `node scripts/site-breaks.js` 를 실행하세요(`--check` 는 확인만 합니다).
- 페이지에는 **서명·공증되지 않은 앱**이라는 안내(우클릭 → 열기, 키체인 암호 창)와 **모델 미포함**(Ollama 필요) 안내가 들어 있습니다.

## 명령줄에서 서버 접속 (`--ssh=호스트`)

다른 프로그램(예: 메뉴바의 서버 목록)에서 MacAIterm 의 새 탭으로 SSH 접속을 열 수 있습니다.

```bash
open -n -a "MacAIterm" --args --ssh=ubuntu            # ~/.ssh/config 의 별칭
open -n -a "MacAIterm" --args --ssh=deploy@192.0.2.10
```

- 값은 반드시 `--ssh=호스트` 처럼 `=` 로 붙여 쓰세요 (실행 중인 앱에 전달될 때 인자 순서가 바뀌어 띄어 쓰면 값을 잃을 수 있습니다).
- 이미 실행 중이면 새 창을 띄우지 않고 실행 중인 앱에 새 탭을 만들어 접속합니다 (프로필당 하나만 실행).
- 접속 대상은 `user@host` 또는 `~/.ssh/config` 별칭만 받습니다. `-o…` 같은 옵션이나 셸 문법이 들어간 값은 무시합니다.
- 비밀번호는 다루지 않습니다. 터미널에서 직접 입력하거나 키 인증을 쓰세요.
- 여러 개를 따로 띄워야 한다면 `AIT_NO_SINGLE_INSTANCE=1` 로 잠금을 끌 수 있습니다.

## 사용할 LLM

> **모델은 앱에 포함되어 있지 않습니다.** 사용자가 **직접 내려받아야** 하고, 내려받은 모델이 앱의 **모델 목록(상단 모델 칩 → `Ollama` 경로 → "설치된 모델")** 에 나타나야 사용할 수 있습니다. 앱은 모델을 자동으로 내려받거나 설치하지 않습니다.

### 처음 사용하는 순서 (필수)

| 단계                       | 할 일                                                                                                                                          | 확인 방법                                                             |
| -------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------- |

### OpenAI API 키 사용 (환경변수 `OPENAI_API_KEY`)

> OpenAI 의 호스팅 모델을 쓰려는 경우에만 필요합니다(대화 문맥이 OpenAI 로 전송되고 **토큰 요금이 부과**됩니다). 기본 경로(Ollama 로컬)는 키가 필요 없습니다.

| 변수                           | 용도                                                  | 지정 방법                                                                    |
| ------------------------------ | ----------------------------------------------------- | ---------------------------------------------------------------------------- |
| **`OPENAI_API_KEY`**   | AI 요청에 쓰는 API 키                                 | 터미널에서`export OPENAI_API_KEY="…"` — 매번 쓰려면 `~/.zshrc` 에 추가 |
| **`OPENAI_ADMIN_KEY`** | **공식 사용량 조회**(조직 관리자 키, 아래 참고) | `export OPENAI_ADMIN_KEY="…"`                                             |

**순서**

1. 키를 지정하고 **앱을 다시 실행**합니다. Dock 에서 켠 앱은 `~/.zshrc` 의 변수를 물려받지 못하므로, 앱이 시작할 때 **로그인 셸에서 `OPENAI_API_KEY` / `OPENAI_ADMIN_KEY` 를 읽어 옵니다**(이미 설정된 값은 덮어쓰지 않음). 값은 화면·로그·파일 어디에도 남기지 않습니다.
2. 설정이 되었는지 터미널에서 확인합니다.

   ```bash
   echo $OPENAI_API_KEY             # 키 값이 그대로 출력됩니다 (화면 공유·녹화 중에는 주의)
   echo ${OPENAI_API_KEY:+설정됨}   # 값은 숨기고 설정 여부만 출력
   ```
3. 앱 **설정(⌘,) → "OpenAI 호환 서버"** 에 서버 주소 `https://api.openai.com/v1` 를 입력하고, **모델 칩 → `OpenAI 호환` → `사용`** 을 누릅니다. 설정의 **API 키 (OPENAI_API_KEY)** 줄에 `환경변수 OPENAI_API_KEY 사용 중` 이 표시되면 연결된 것입니다.

**키 우선순위와 안전장치**

- 환경변수 `OPENAI_API_KEY` → (없으면) 설정 창에서 입력해 **키체인에 암호화 저장**한 키 순서로 씁니다.
- **환경변수 키는 OpenAI 공식 서버(`api.openai.com`)에만 전송**됩니다. LM Studio·게이트웨이 등 다른 서버에는 쓰지 않고, 그 서버용으로 설정 창에 저장한 키만 씁니다(실수로 다른 주소를 입력해도 OpenAI 키가 새어 나가지 않도록).
- 설정 창은 키의 **출처**(환경변수 / 키체인 / 없음)만 보여주고 값은 절대 표시하지 않습니다.

**토큰 사용량 보기** — 설정 창의 **"API 토큰 사용량"** 섹션

| 구분                              | 내용                                                                        | 출처                                                                                                                                                                                                                                                                                                |
| --------------------------------- | --------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **이 앱에서 보낸 토큰**     | 이번 실행·오늘·최근 7일·30일의 입력/출력/캐시 토큰, 호출 수, 모델별 합계 | 호출마다**API 응답에 들어 있는 실제 `usage` 값**을 기록(대화 내용은 저장하지 않고 토큰 수만 저장). 응답에 사용량이 없는 서버는 글자 수 기반 **추정**으로 표시하고 따로 표기                                                                                                           |
| **공식 사용량 (조직 전체)** | 오늘·7일·30일 입력/출력/캐시 토큰, 요청 수,**비용(USD)**, 모델별    | OpenAI 의**Usage API (`/v1/organization/usage/completions`)** 와 **Costs API (`/v1/organization/costs`)**. 이 앱 밖에서 쓴 양까지 포함. **조직 관리자 키(`OPENAI_ADMIN_KEY`)** 가 필요하고(일반 키로는 조회 불가), **[공식 사용량 불러오기]** 를 누를 때만 조회합니다 |

- 매 요청이 끝나면 AI 대화창에 `토큰 입력 N · 출력 M` 이 표시되고, 상단 바에는 이번 실행의 누적 토큰이 표시됩니다.
- 공식 사용량은 OpenAI 서버의 집계라 **반영에 시간이 걸릴 수 있고**, 앱이 센 값과 다를 수 있습니다(다른 도구의 사용량 포함, 캐시·반올림 차이). 설정 창의 **[공식 사이트에서 보기]** 로 사용량 대시보드(platform.openai.com/usage)도 열 수 있습니다.
- 공식 사용량 조회는 **OpenAI 공식 서버를 쓸 때만** 제공됩니다(다른 서버는 위 "이 앱에서 보낸 토큰"만 표시).
- 관리자 키는 [조직 설정 → Admin keys](https://platform.openai.com/settings/organization/admin-keys) 에서 조직 관리자가 발급합니다.

## Vim (Python · C · C++ · Rust · Shell)

앱 안의 터미널에서 `vim`(또는 `vi`)을 실행하면 번들 설정이 자동 적용됩니다. 외부 플러그인 없이 Vim 9 내장 기능과 번들 스크립트(`src/main/shell-integration/vim/`)만 사용하며, 사용자의 `~/.vimrc` 는 번들 설정 **뒤에** 로드되어 우선합니다.

**키 표기(Mac)**: `Space` = 스페이스바(리더 키) · `⌃` = Control · `fn` = 왼쪽 아래 fn 키 · `esc` = Esc. 앱 자체의 단축키는 `⌘`(Command), vim 안의 키는 `Space`/`⌃`를 씁니다(둘이 겹치지 않음).

### 기본 단축키 안내

MacBook 에서 `F1~F12` 는 기본이 **밝기·볼륨 같은 미디어 키**라서 기능 키는 `fn` 을 함께 눌러야 합니다(시스템 설정 → 키보드에서 "F1, F2 등의 키를 표준 기능 키로 사용"을 켜면 fn 없이 동작). 그래서 모든 기능 키에 **fn 이 필요 없는 짝 키**를 만들었습니다.

복사·붙여넣기: vim 의 `y`/`p` 는 **macOS 클립보드와 공유**됩니다(`clipboard=unnamed`). 즉 vim 에서 `y` 로 복사한 것을 다른 앱에서 `⌘V` 로, 다른 앱에서 `⌘C` 한 것을 vim 에서 `p` 로 붙여넣을 수 있습니다. 앱 안에서 `⌘V` 로 붙여넣으면 bracketed paste 로 안전하게 들어갑니다.

### 화면

- **줄 번호**(현재 줄 절대 / 나머지 상대), 들여쓰기 가이드(`│`)·줄 끝 공백 표시, 언어별 길이 제한선(Python 88 · C 80 · C++/Rust 100 · Shell 80)
- **상태줄**: 모드별 색, git 브랜치·변경량, 오류/경고 수, 파일 형식, 위치. 앱 테마(다크/라이트)와 연동된 컬러 스킴
- **줄 왼쪽 표시**: git 변경(▎ 녹색 추가 · 파랑 수정 · 빨강 삭제), 검사 결과 `●`, `TODO/FIXME/BUG` 강조, 커서 아래 단어와 같은 단어 강조
- 언어별 설정: Python(4칸), C/C++(`cindent`), Rust(4칸), Shell(2칸)

### AI 수정과 LSP

- **`:AitAI`** — 앱 안의 vim 이 비공개 이스케이프 시퀀스로 요청을 보내면 앱이 **선택한 모델**에 묻고 답을 임시 파일로 돌려줍니다(vim 은 편집을 계속할 수 있고 상태줄에 `✦ AI…`). 그 사이에 해당 줄이 바뀌었으면 적용하지 않습니다.
- **LSP** — vim 내장 JSON-RPC 채널만 사용하며 서버를 **내려받지 않습니다**(설치되어 있을 때만 동작, 끄기: `AIT_LSP=0`). 실제 clangd 로 진단·정의 이동·hover 를 시험했습니다. rust-analyzer 경로는 검증 환경에 구성 요소가 없어 **미검증**입니다(설치되지 않은 rustup 프록시는 자동으로 건너뜀).

### 설정

- 끄기: `AIT_VIM=0` 또는 `vim -u NONE`. 테마 전환은 **새로 여는** vim 부터 반영(열린 vim 은 `:AitTheme dark|light`).
- 앱의 터미널은 `Option(⌥)` 을 **Meta 키**로 보냅니다(`⌥`+글자 = `esc` 접두). 그래서 `⌥` 로 특수문자를 입력하는 기능은 이 터미널에서는 쓰지 않습니다.

## 개발

요구: macOS, Node 20+, zsh. (Qt 대신 Electron + xterm.js + node-pty 를 쓴 이유: 검증된 터미널 렌더러·PTY·한글 IME 를 바로 얻고 VT 에뮬레이터를 직접 만들 필요가 없음)

```bash
npm install
npm start                                  # 개발 실행 (AIT_CWD 로 시작 디렉터리 지정)
npm test                                   # 단위 테스트 (KV·압축·엔진·사용량·키·정책·기록·vim LSP(실제 clangd) 등)
npm run e2e:features                       # 새 기능 종단 시험: 실제 Electron + 실제 PTY + 모의 모델 서버(GPU·네트워크 불필요)
npm run i18n:check                         # 화면 문구 키가 ko/en 모두 있는지
npm run test:native                        # C++ 도구(native/) 빌드 + 자체 테스트 (brew install llama.cpp 필요)
npm run e2e                                # 실제 앱 + 실제 LLM 종단 시험 (임시 프로필 사용, 사용자 설정을 건드리지 않음)
node scripts/e2e.js <시나리오...>          # shell tabs perm approve_yes unload vim llmdown ui shots ...
node scripts/bench.js qwen3:8b qwen3:14b   # 모델 성능 측정
node scripts/headless.js <dir> "<요청>"    # UI 없이 에이전트 흐름만
npm run dist                               # DMG/ZIP 생성
node scripts/e2e-features.js ssh           # SSH 화면 종단 시험(임시 sshd, 세션 관리자 → 접속 → 서버 모니터 → 폴더 트리·드래그 복사 → 서버에서 AI)
node scripts/shots-ssh.js                  # SSH 문서용 스크린샷(설치된 앱: AIT_APP_BIN, AIT_DOC_PROMPT 참고)
```

## 동작 원칙

- **입력 구분**: AI 모드의 입력은 셸로 가지 않고(`!명령` 만 셸 실행), 셸 모드·터미널에 직접 친 한글 문장이나 알 수 없는 명령형 문장은 실행하지 않고 AI로 넘깁니다.
- **자동 실행**: 읽기 전용 조사, 일반 개발 작업(테스트·빌드·작업 디렉터리 안의 파일 수정).
- **승인 필요**: `rm`, `sudo`, `git push`/`reset --hard`/`clean`/강제 옵션, 외부 전송(`curl -d`, `scp`…), `kill`, 작업 디렉터리 밖 쓰기, 비밀 파일 접근, 전역 설치, 셸 프롬프트(`PS1`) 변경 등. 승인은 정확히 그 명령·디렉터리에 대해 1회만 유효하고 명령이 바뀌면 다시 묻습니다.
- **차단**: `rm -rf /`·`~`, 디스크 포맷/직접 쓰기, vim 등 대화형 프로그램, 여러 줄 명령. 비밀번호(sudo 등)는 터미널에서 사용자가 직접 입력하며 AI는 보지 못합니다.
- **프롬프트 주입 방어**: 파일·명령 출력은 `<untrusted_*>` 로 감싸 데이터로만 취급합니다.
- **비밀 보호**: API 키·토큰·비밀번호 패턴 마스킹, `.env`/`id_rsa` 등은 읽지 않음, 인증 정보는 로그에 남기지 않음.
- **되돌리기**: 파일 변경 카드의 "이 변경 되돌리기", 원본은 `~/Library/Application Support/MacAIterm/backups`.
- **중단**: 중단 버튼 / ⌘. / Esc — 모델 호출 취소 + 실행 중 명령에 Ctrl+C.

## 참고 사항

- AI 실행 연동은 zsh·bash·fish(fish 는 실행 미검증)와 원격(SSH) 모드(임시 `sshd` 기준으로 시험, 실제 서버 조합은 일부만 검증), Apple Silicon 빌드 기준(Intel 빌드는 만들 수 있으나 실행은 미검증). 앱은 **서명·공증되지 않았습니다**(최초 실행 시 우클릭 → 열기) — 그래서 업데이트는 확인만 하고 자동 설치하지 못합니다.
