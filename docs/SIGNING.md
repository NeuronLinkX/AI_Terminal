# 앱 서명 (고정 인증서)

빌드할 때마다 서명이 바뀌면 macOS가 새 빌드를 **다른 앱**으로 취급해서, 앱에 준 권한이 사라집니다.
이 문서는 고정 인증서로 서명해서 권한이 재빌드와 업데이트를 넘어 이어지게 하는 방법입니다.

## 왜 필요한가

macOS의 앱별 권한(로컬 네트워크, 키체인 "항상 허용" 등)은 앱의 **코드 신원**에 묶여 있습니다.

- 지금까지의 서명(`ad-hoc`)은 빌드 내용에서 계산한 값이라 **빌드할 때마다 다릅니다.**
- 그래서 다시 빌드해 설치하면 이전에 허용한 "로컬 네트워크" 접근이 이어지지 않고, 집 안의 서버(`192.168.x.x`)에 접속하면 앱 터미널에서만 `No route to host`가 납니다.
- 같은 인증서로 서명하면 신원이 `identifier "com.neuronlinkx.macaiterm" and certificate leaf = H"인증서 해시"`로 고정되어 빌드가 바뀌어도 같습니다.

## 한 번만 하는 일

터미널에서 직접 실행하세요.

```bash
cd /Users/juhee/Desktop/workspace/AI_terminal && scripts/make-signing-cert.sh
```

- `MacAIterm Local Signing` 인증서를 만들어 **로그인 키체인**에 넣습니다(10년 유효).
- macOS가 로그인 비밀번호나 Touch ID를 묻는 창을 띄울 수 있습니다. 그 창에 직접 입력하세요. 스크립트는 비밀번호를 보지 못합니다.
- 신뢰 설정을 바꾸지 않고 관리자 권한도 필요 없습니다. 이미 있으면 아무것도 하지 않습니다.
- 첫 빌드에서 "codesign이 키를 사용하려 합니다" 창이 뜨면 비밀번호를 입력하고 **항상 허용**을 누르세요.

## 빌드

평소처럼 빌드하면 됩니다.

```bash
npm run dist
```

빌드 로그에 어느 신원으로 서명했는지 한 줄 나옵니다.

- `signed with "MacAIterm Local Signing"`: 고정 신원. 권한이 이어집니다.
- `signed ad-hoc`: 인증서가 키체인에 없어서 예전 방식으로 서명했습니다. 빌드는 되지만 빌드마다 신원이 달라집니다.

서명은 두 단계입니다(`build/sign-after-pack.js`).

1. 앱 안의 모든 조각(메인 실행 파일, 헬퍼, 프레임워크)을 빠른 임시 서명으로 서명합니다.
2. macOS가 앱을 식별하는 **겉 번들**만 고정 인증서로 다시 서명합니다. 안쪽은 건드리지 않아서 몇 초면 끝납니다. 인증서로 모든 파일을 서명하면 이 Mac에서 7분 넘게 걸렸습니다.

두 단계 모두 `build/entitlements.mac.plist`의 같은 권한(JIT 허용, **라이브러리 검증 해제**)을 줍니다. 겉 번들과 안쪽 조각의 서명자가 다르기 때문에 라이브러리 검증을 끄지 않으면 앱이 시작 직후 `Electron Framework ... have different Team IDs` 오류로 종료됩니다(시험으로 확인했습니다). 이 파일을 지우거나 권한을 빼지 마세요.
시각 서버(타임스탬프)는 쓰지 않아서 오프라인에서도 빌드됩니다.

## 확인

설치한 앱과 새 빌드의 신원이 같은지 봅니다. 두 줄의 `H"…"` 값이 같아야 합니다.

```bash
codesign -dr - /Applications/MacAIterm.app
```

서명이 온전한지도 확인합니다.

```bash
codesign --verify --deep --strict /Applications/MacAIterm.app && echo ok
```

## 처음 한 번은 다시 허용해야 합니다

고정 인증서로 서명한 첫 앱은 macOS에게 **새 앱**입니다. 한 번만 다시 허용하면 이후 빌드에서는 유지됩니다.

- 로컬 네트워크: 시스템 설정 > 개인정보 보호 및 보안 > 로컬 네트워크에서 MacAIterm을 켭니다. 앱에서 집 안의 서버에 접속할 때 허용 창이 뜨면 허용하세요.
- 키체인: "MacAIterm Safe Storage" 질문이 한 번 나옵니다. 비밀번호를 직접 입력하고 **항상 허용**을 선택하세요.

## 백업

개인 키는 **이 Mac의 키체인에만** 있습니다. 잃어버리면 새 인증서가 필요하고, 그때는 신원이 바뀌어 권한을 한 번 다시 줘야 합니다.

1. 키체인 접근 > 로그인 > 내 인증서 > `MacAIterm Local Signing` > 우클릭 > 내보내기 (`.p12`, 직접 정한 비밀번호).
2. 파일은 비밀번호 관리자나 암호화된 곳에 보관하세요. 저장소에 넣거나 다른 사람에게 보내지 마세요.

다른 Mac에서도 같은 신원으로 빌드하려면 그 `.p12`를 키체인에 가져오면 됩니다.

## 확인한 것

임시 키체인에서 시험했고(사용자 키체인은 건드리지 않았습니다), 결과는 다음과 같습니다.

- 내용이 다른 두 빌드가 같은 신원 `identifier "com.neuronlinkx.macaiterm" and certificate leaf = H"…"`을 가졌습니다. 인증서 없이 서명한 두 빌드는 `cdhash`가 서로 달랐습니다.
- 인증서로 서명한 앱과 대체(ad-hoc) 서명 앱이 모두 시작되고 `codesign --verify --deep --strict`를 통과했습니다. 전체 `npm run dist`(DMG 포함)와 DMG에서 꺼낸 앱의 시작도 확인했습니다.
- 신뢰 설정 없이도 `codesign`이 서명했습니다(`CSSMERR_TP_NOT_TRUSTED`로 표시되지만 서명과 신원 고정에는 영향이 없습니다).

## 한계

- 이 인증서는 macOS가 **신뢰하지 않는** 자체 서명입니다. 다운로드한 앱의 Gatekeeper 경고("확인되지 않은 개발자")는 그대로입니다. 공증이 필요하면 Apple Developer Program의 Developer ID가 필요합니다.
- 배포하는 모든 DMG를 같은 인증서로 서명하면 사용자 Mac에서도 업데이트 때 권한이 이어집니다. 이 점이 ad-hoc 서명과 가장 큰 차이입니다.
- macOS가 새 신원의 앱에 로컬 네트워크 허용 창을 띄우는지는 이 저장소에서 완전히 확인하지 못했습니다. 이미 거부 기록이 있는 앱에는 창이 뜨지 않았습니다. 창이 안 뜨면 위의 설정 화면에서 켜고, 목록에 없으면 앱을 터미널에서 실행해 보세요(`docs/SSH.md`의 로컬 네트워크 권한 항목).
